# 招待・再開・退出の改善（2026-11-02）

## 対応

- Web Locksを使えるブラウザーでは、同じタブ識別子を持つ別ドキュメントからのゲスト席取得を防ぐ。複製側はゲストの秘密情報だけを破棄し、アカウント席は維持する。ページを離れたときにロックを解放し、戻る操作では再取得する。
- 保存対局は参加者・参加待ち／対戦中・参加方法を記録する。秘密トークンは共有の保存一覧には書かない。
- 元のゲスト席を復元できないタブには理由を表示し、観戦へ誘導する。アカウントが異なる場合も再開できると表示しない。同一ブラウザーでアカウント参加とゲスト参加が混在しても、既知のアカウントの復帰先を保持する。
- 設定内に該当ゲームのオンライン対局も一覧表示する。同一路径のデッキ／タイル、リバーシ／四目並べを混同しない。終了済み対局の削除は共通通知を発火する。
- 安全なreturnToを開始URLへ付与し、共通ヘッダーが優先して使用・保存する。外部サイトや対戦URLを戻り先に指定できない。
- コミュニティ作品の概要画面と直接プレイ入口もGameSetupを使用する。人数・対戦方法・開始操作・保存対局を集約し、版を固定する。
- 旧版ルームに共通ヘッダーと旧版表示を追加。コード作品は試遊版と表示し、席を使う前にタブの準備を行う。
- ローカルHTTPプレビューでも暗号学的乱数によるUUID v4生成を使用する。

## 検証

- 97件の自動テスト、型チェック、本番ビルドが成功。自動テストは既存のルーム認証・非公開情報・再戦・保存削除の検証に加え、複製タブ、ゲスト再開、アカウント切替、同一ルームの保存共有、オンライン保存の通知、版固定設定、戻り先の検証を追加。
- ローカルブラウザーでカラハの設定→招待ルーム作成→別タブの参加方法選択→別ゲスト参加を確認。AとBがそれぞれ別席として表示され、Aの手番にBは操作できなかった。
- Bがホームへ戻ると参加者付きの保存対局を表示。ゲーム設定シート内にも同じオンライン対局が出ることを確認。参加していない第三のタブでは、元のタブで再開する説明と「ルームを見る」を表示し、watch=1付きの観戦URLへ遷移した。

## 残る確認と範囲

- プレビューはHTTPのためWeb Locksを使う実ブラウザーの複製タブ検証はできていない。ロック競合と再取得はモックを使ったテストで確認。HTTPS環境でタブ複製・再読み込み・戻る／進むを実機確認すること。
- Web Locks非対応ブラウザーでは従来のタブ保存へフォールバックする。公開招待URLでの明示的な参加方法選択は維持する。
- Google OAuth、本番の複数アカウント、モバイルの実機表示、旧版ルームおよび隔離コード作品の完全な認証統合は今回のブラウザー確認対象外。旧版とコード作品の席プロトコルを変更したとは扱わない。
- ローカル修正／PR作成の範囲。本番の秘密設定やデータベースは変更しない。
