# アプリ内制作を標準にする

## 方針

作者がGitHub・フォルダ構成・実行環境を理解することを開始条件にしない。作品名を決めたら、動くゲームから始め、相談・編集、試遊、公開までを作品画面に集める。JSONの設定変更に閉じず、ゲームのルールとUI自体をTypeScript / HTMLで派生できる。

## 実装済み

- 作品作成時に島の工房のソースを下書きへ用意。既存作品は初回表示時に最新版から下書きを作る。
- 変更依頼とコードの自動保存（1.2秒後）。revisionによる競合検出、保存状態、失敗時の編集保持、離脱警告。
- アプリ内でルール・UI・ゲームモジュールを編集。SDKと派生元・ライセンス情報を保護。
- 接続済みの制作AIから完全一致の変更パッチを受け取り、構文変換とファイル検証後に下書きへ適用。直前のAI変更を戻せる。API未設定時は利用できないことを明示。
- 試遊は固定した版を作成して同じ画面に表示。変更後は再試遊するまでその変更を公開できない。旧版の明示選択で公開版を戻せる。
- 公開は作者の操作。試遊URLを共有しても制作画面や所有トークンを渡さない。
- GitHub設定済みの場合は試遊時にソース同期。失敗は表示し、D1の下書きと試遊版を保持。GitHub接続・アップロードは詳細設定。

下書きはD1の `code_drafts` に保存。通常のGitHub Push取り込みは既存下書きを上書きしない。高度な開発者がGitHubとアプリ内編集を併用する場合の差分統合UIは今後対応する。

## 運営側の残作業

1. 作成済みGitHub Appの秘密鍵を本人操作で発行し、管理用リポジトリだけにインストール。Cloudflare Secretsと変数を設定する。
2. 本番の隔離環境でCPU制限・通信遮断・出力上限を確認してからオンライン試遊を有効化。
3. 制作AIを接続する。現実装は既存OpenAI接続を利用し、作者1人5回/日・全体20回/日で制限。無料枠の保証はない。モデルのJSON出力と実際の変更成功率を確認する。
4. 初心者3人に、船の追加などの変更依頼から試遊・公開まで観察テスト。完了率、途中離脱、エラー回復率を記録。

## 次の改善

- ファイル追加・削除、コード差分確認、安定版への下書き復元。
- AI処理の進捗とキャンセル、ゲーム動作テスト、コンパイル失敗を説明する修復フロー。
- 自然言語以外にも使えるルール・見た目の簡単な操作。ただしコードの自由度は維持する。
- 他のひな形、実例付きチュートリアル、作者への試遊フィードバック保存。

## 検証

88個の単体・統合テスト、型検査、production buildに成功。HTTP smokeで作品作成、自動下書き、保存と再取得、AI未接続の処理、GitHubなしの隔離試遊、2席の対戦、作者のみの公開と一覧掲載を実ランタイムで確認。GitHubの実同期と本番AI・CPU打ち切りは未確認。ローカルChromiumが取得できずブラウザの自動テストは未実行。
