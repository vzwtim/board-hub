# 制作は依頼・レビュー・試遊を中心にする

2026-11-20時点の方針。アプリ内の生成AIによる相談・リアルタイム編集は次のフェーズへ移す。現行画面は外部AI・開発者に依頼し、戻ってきたソースを確認して採用する。

## 使い方

1. 作品を作る。島の工房を元に動く下書きを用意する。
2. 改良依頼をメモし、「依頼セットをダウンロード」。現在の全ソース、BOARDHUB_REQUEST.md、照合用boardhub-review.jsonをZIPにまとめる。古いチャット履歴やAPIキーは含めない。
3. 開発者・ChatGPT・CodexなどへZIPと依頼を渡す。GitHub利用時はブランチとPRでレビューする。
4. 完成フォルダを選び、変更前後のソースを確認する。サーバーで検証・コンパイルしてから候補として試遊する。この時点では保存中のコードを上書きしない。
5. 動きを確認して「この版を採用」。保存済みの下書きが新しい版になる。直前の採用は戻せる。公開中の版は変更しない。

## 制約と保護

- 通常の作業はアプリ内AI、GitHub App、オンライン実行環境の設定に依存しない。
- 元ソースの指紋とrevisionで古い成果物の上書きを検出する。依頼メモだけの変更は指紋に影響しない。
- 編集可能なgame.ts・ui.html・manifest.json・games/・assets/を取り込む。実行基盤は元のファイルを保持し、派生元・ライセンスの書き換えは拒否する。
- インポートは追加・置き換え。フォルダから省略した既存ファイルは削除しない。
- ZIPの入力は展開してからフォルダ選択。80ファイル、合計400KB、1ファイル200KBまで。
- 試遊はブラウザーの隔離Workerで実行。オンライン公開・GitHub同期は詳細欄に置き、接続状態を明示する。
- 旧生成APIは互換性のため残すが、標準制作画面からは呼ばない。モデル選択・APIキー入力・チャットは標準導線に出さない。

## ゲーム追加

将棋とチェスをカタログに追加。CPUは専用ブラウザーWorkerで動き、外部AI APIを使わない。CPUとの練習、同じ画面で2人、途中保存、盤面反転、投了、一手戻しに対応。現段階ではオンライン招待に非対応。

将棋は通常の駒移動・成り・持ち駒・二歩・打ち歩詰め・王手放置・千日手・連続王手・27点入玉宣言を判定する。千日手は勝敗なしの終局として指し直す。

チェスはchess.js（BSD-2-Clause）で合法手を検証。キャスリング、アンパッサン、4種類の昇格、チェックメイト、ステイルメイト、戦力不足を扱う。同一局面3回・50手ルールはカジュアル対局用に自動適用する（大会の申告手順ではない）。持ち時間は設けない。
